# Справочник: пополнение каталога растений из Perenual

Файл лежит рядом со скриптами: `backend/scripts/PERENUAL.md`.

## 1. Карточка на каждый день

Все команды из папки `backend`, с активным venv, при запущенной базе данных (`docker-compose up -d`).

```powershell
cd "D:\new folder\учёба\floraguide-ai\backend"
.\venv\Scripts\activate

python scripts/perenual_bulk.py daily        # потратить лимит и записать новые растения в БД
python scripts/reindex_embeddings.py         # посчитать векторы для новых растений
python scripts/perenual_bulk.py status       # посмотреть итог
```

Команда `daily` сама выполняет три шага:

| Шаг | Что делает | Сколько запросов |
|---|---|---|
| 1. Список | постранично собирает id растений (30 штук на страницу) | 1 запрос на страницу |
| 2. Карточки | скачивает данные ухода для каждого растения | 1 запрос на растение |
| 3. Запись в БД | создаёт новые растения из скачанного (без сети) | 0 |

Когда лимит (90 запросов) исчерпан, скрипт останавливается и сохраняет всё скачанное. На следующий день повторите ту же команду: уже скачанное повторно не запрашивается.

Раз в несколько дней добавляйте русские названия (раздел 4).

## 2. Что где лежит и что куда вводить

| Что | Где | Вводить ли руками |
|---|---|---|
| Ключ API | `backend/.env`, строка `PERENUAL_API_KEY=...` | один раз |
| Русские названия, описания, категории | `backend/scripts/names_ru.yaml` | да, это ваша работа |
| Кэш ответов Perenual, счётчик запросов, список растений | `backend/scripts/cache/` | нет, создаётся сам, в Git не попадает |
| Скрипты | `backend/scripts/*.py` | нет |
| Итоговые данные | таблица `plant_species` в БД | нет, пишет скрипт |

Старые команды (`import_perenual.py search/details/load` и список `plants_list.py`) нужны только для первых 18 растений из сида. Для новых растений они не нужны.

## 3. Первый день

1. Убедитесь, что миграция применена, ключ в `.env`, база запущена:
   ```powershell
   alembic current
   python scripts/perenual_bulk.py status
   ```
   `status` покажет «Запросов потрачено сегодня: 0 из 90».
2. Запустите `python scripts/perenual_bulk.py daily`. Скрипт сначала соберёт список (для комнатных растений, `indoor=1`), потом начнёт скачивать карточки.
3. В конце вы увидите, сколько растений доступно и сколько осталось скачать, например «Осталось скачать карточек: 320, это примерно 4 дн.». Эта оценка и есть ваш план: столько дней нужно запускать `daily`.
4. Выполните `python scripts/reindex_embeddings.py` и проверьте сайт: новые растения появятся в каталоге и в поиске.

Бесплатный ключ видит только растения с id до 3000. Скрипт останавливает сбор списка, когда две страницы подряд состоят из недоступных id, чтобы не тратить запросы впустую.

## 4. Русские названия

Новые растения из Perenual получают английские названия и пустое описание. На русскоязычном сайте это допустимо временно, лучше переводить.

```powershell
python scripts/perenual_bulk.py names-export     # добавит в names_ru.yaml заготовки для скачанных растений
```

Откройте `scripts/names_ru.yaml` и заполните поля:

```yaml
plants:
  Monstera adansonii:
    english: Swiss Cheese Vine      # подсказка, не меняйте
    name: Монстера Адансона         # заполните
    category: Комнатные растения    # проверьте: определяется приблизительно
    description: Лиана с овальными листьями, в которых прорезаны отверстия.
```

Применить к уже добавленным растениям:

```powershell
python scripts/perenual_bulk.py names-apply --dry-run   # посмотреть, что изменится
python scripts/perenual_bulk.py names-apply
```

Если заполнили названия до добавления в БД, `add` и `daily` подставят их сами. Если нужно, чтобы в каталоге были только растения с русским названием, добавляйте с ключом `--only-named`:

```powershell
python scripts/perenual_bulk.py daily --only-named
```

Допустимые категории: `Комнатные растения`, `Суккуленты и кактусы`, `Цветущие растения`, `Папоротники и пальмы`. Категория по умолчанию определяется по семейству и названию растения. Это грубая эвристика (например, кактусы и пальмы определяются хорошо, а цветущие растения хуже), поэтому проверяйте и поправляйте поле `category`.

Описания пишите своими словами. Тексты Perenual скрипт не копирует.

## 5. Все команды

| Команда | Что делает |
|---|---|
| `daily` | список, карточки до лимита, запись в БД |
| `status` | расход запросов, размер списка, число растений в БД |
| `discover` | только собрать список (`--pages 5` ограничивает число страниц) |
| `pull` | только скачать карточки (`--limit 40`, `--retry-failed`) |
| `add` | только записать скачанное в БД (`--dry-run`, `--only-named`, `--allow-no-care`) |
| `names-export` | заготовки для русских названий |
| `names-apply` | применить `names_ru.yaml` к БД (`--dry-run`) |

Полезные ключи: `--max-requests 90` (суточный лимит), `--reserve 10` (оставить запросы про запас), `--no-add` (только скачать), `--include-cultivars` (включать сорта).

## 6. Как расширить список

По умолчанию берутся комнатные растения без сортов. Чтобы добавить другие, добавляйте фильтры (список растёт, прогресс по каждому набору фильтров хранится отдельно):

```powershell
python scripts/perenual_bulk.py daily --filter watering=minimum        # только засухоустойчивые
python scripts/perenual_bulk.py daily --filter poisonous=1             # только ядовитые
python scripts/perenual_bulk.py daily --query orchid                   # поиск по названию
python scripts/perenual_bulk.py daily --no-indoor                      # не только комнатные (в основном садовые)
python scripts/perenual_bulk.py daily --include-cultivars              # сорта
```

Допустимые фильтры `species-list`: `watering` (frequent, average, minimum, none), `sunlight` (full_shade, part_shade, sun-part_shade, full_sun), `indoor`, `poisonous`, `edible`, `cycle`, `hardiness`.

## 7. Что делать, когда список закончился

Количество растений до id 3000 конечно, поэтому через несколько дней `daily` напишет «Все доступные карточки скачаны». Тогда:

1. Расширьте набор фильтрами из раздела 6, если нужны ещё растения.
2. Переведите и пополните описания (раздел 4): для демонстрации это ценнее новых английских записей.
3. Пополняйте базу знаний экспертной системы: перечень болезней и вредителей в Perenual (`pest-disease-list`, доступны записи с id 1-100 по вашему плану) можно использовать как ориентир для новых причин и правил. Скрипта для этого нет, при необходимости его можно добавить.
4. Не тратите запросы впустую: счётчик нужен только для защиты от блокировки, переносить остаток на другой день нельзя.

## 8. Для Git

| Коммитить | Не коммитить |
|---|---|
| `perenual_bulk.py`, `import_perenual.py`, `plants_list.py`, `reindex_embeddings.py` | `scripts/cache/` |
| `names_ru.yaml` (ваши переводы) | `.env` с ключом |
| `PERENUAL.md` | дамп базы с данными Perenual |

Данные Perenual в репозиторий не кладём: это чужие данные на условиях бесплатного тарифа. Напарнику достаточно получить свой ключ, выполнить `git pull` и запускать `daily`: переводы из `names_ru.yaml` подтянутся из репозитория.

## 9. Проблемы и решения

| Сообщение или симптом | Причина и решение |
|---|---|
| `Нет ключа. Добавьте в backend/.env ...` | в `.env` нет `PERENUAL_API_KEY` или нет значения |
| `Ключ не принят сервером` | неверный ключ, перевыпустите на perenual.com |
| `Сервер сообщил, что лимит исчерпан (429)` | лимит на стороне Perenual, продолжите завтра: кэш сохранён |
| `Дневной бюджет исчерпан` | сработал локальный лимит (90), это нормально |
| `В модели PlantSpecies нет колонок ...` | не применена миграция этапа 2: `alembic upgrade head` |
| `Запись в БД пропущена` или `База данных недоступна` | не запущен контейнер: `docker-compose up -d`. Скачанное в кэше, повторите `add` |
| `нет данных ухода (закрыты тарифом)` | тариф не отдал поля этого растения, оно пропускается (`--allow-no-care` добавит его без данных) |
| у растения в каталоге нет влажности и срока роста | Perenual этих данных не даёт, заполните вручную или оставьте пустыми |
| у растения английское название | заполните `names_ru.yaml` и выполните `names-apply` |
| растение в неверной категории | поле `category` в `names_ru.yaml`, затем `names-apply` |

Начать сбор заново: удалите `scripts/cache/candidates.json` (прогресс по списку; сами страницы списка лежат в кэше и повторно запросов не тратят) или всю папку `scripts/cache/` (всё скачанное, запросы будут потрачены заново).

Убрать из БД растения, добавленные скриптом: сначала посмотрите список в pgAdmin и удаляйте только то, что точно добавлено им.

```sql
SELECT id, name, scientific_name, external_id FROM plant_species ORDER BY id;
```

Растения из сида имеют самые маленькие id (первые 18), добавленные скриптом идут после них. У семи растений из сида тоже заполнен `external_id` (после `import_perenual.py load`), поэтому условие «`external_id` не пустой» для удаления использовать нельзя. Растение, которое лежит в чьём-то профиле (`user_plants`), база удалить не даст: сначала нужно убрать его из профилей.

## 10. Что сказать в отчёте

- Данные ухода (полив, освещение, токсичность, сложность) загружаются из Perenual один раз скриптами и хранятся в собственной базе; приложение сторонний сервис при работе не вызывает.
- Скрипты учитывают лимит бесплатного тарифа (счётчик запросов, кэш, остановка при ответе 429).
- Русские названия и описания добавлены вручную; категории определены приблизительно по семейству растения и могут быть исправлены.
- Для растений с id больше 3000 данных нет, бесплатный тариф их не отдаёт.
